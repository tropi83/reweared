# Project context — AI Image Variations

## Product in one paragraph

AI photo studio for second-hand listings (Vinted-style), with an account: import the item's photo → choose category/subcategory (10 → 56, `catalog.ts`) → the **server** generates the listing photos with predefined, kind-specific prompts (retouched / studio / in use or worn / folded or detail, + mirror selfie for wearables except kids) → compare, pick, export; a vision model writes the title + description (Gemini Flash-Lite by default; Cloudflare Llama as alternative). No free prompt. Images = Cloudflare Workers AI (Gemini image generation disabled via `GEMINI_IMAGE_GENERATION_ENABLED`), copy = Gemini by default; both run in the worker with the platform's keys and are paid in credits. Listings can be pre-filled on Vinted (desktop window, native screen on phones), from the device. The earlier local-first, BYOK release (no account, keys on the device) is kept on the **`byok` branch** only.

## The architecture (ADR 0001, 2026-10-11; local mode removed 2026-10-12)

**User accounts + a server** that is the source of truth and runs generations with the **platform's** provider keys: [`docs/adr/0001-backend-accounts-platform-keys.md`](../../../docs/adr/0001-backend-accounts-platform-keys.md), design `docs/superpowers/specs/2026-10-11-backend-queue-accounts-design.md`. Stack: TypeScript/Node in a pnpm workspace sharing `packages/domain`, Fastify api + BullMQ worker (same image), Postgres (drizzle), Redis, SeaweedFS (S3 API), Better Auth, Resend, SSE, credit ledger with a free plan, one VPS with `docker compose` + Caddy. Image provider stays open (Cloudflare by default; the Gemini adapter exists).

## Decisions already taken (do not re-litigate without new facts)

- **Backend pivot (ADR 0001):** platform-owned provider keys (worker only, Docker secrets), accounts with Better Auth (email + password, Google Sign-In), Resend for email, credits reserved at enqueue and refunded on failure, BullMQ + Redis dispatch with Postgres as job state and a per-user cap, SSE, one VPS with docker compose.- **Default image provider = Cloudflare Workers AI**, model **FLUX.2 [klein] 4B** (multipart API, reference image ≤ 512 px, ≈110 neurons per 1K image inside the 10,000 free daily neurons) because Gemini image models have no free tier. SD 1.5 img2img is private on many accounts (5018); SDXL/DreamShaper have no image input (3030) and must not be re-added as img2img. The worker calls Cloudflare server-side with the platform account; the client never calls a provider.
- **One listing card, one button.** `generateListing` runs photos + text with `Promise.allSettled`, skips a part whose provider is unusable and reports both outcomes; the label comes from `listingReadiness` and never promises a part that will not run. One mannequin per device (`Settings.mannequin`), toggled per project (`Listing.useMannequin`), never for kids/pets. The seller's brand (`Listing.brand`) goes to the copy prompt only — never into an image prompt.
- Diffusion providers: input prepared by the worker (sharp) (`ModelCapabilities.inputImage`: crop to ratio, multiples of 64), one random `seed` per job, provider options via `ModelCapabilities.options` + `job.providerOptions`.
- Gemini image generation = **Interactions API** `POST /v1beta/interactions` with `response_format: { type: "image", aspect_ratio?, image_size? }`. `mime_type` is NOT sent (the live API rejected `image/png` on 2026-09-11 despite the docs).
- Model capabilities live only in `GeminiModels.ts` (ids, aspect ratios, sizes). Verified 2026-09-11.
- Secrets on the device: OS keychain via the `keyring` crate (desktop) holds the **session token only**; provider keys live in the server's worker. Not Stronghold (needs a JS-supplied password). Mobile keystore = TODO, session-only meanwhile. The OAuth loopback and Gemini credentials code were removed with the local mode (see `byok`).
- **The aggregate is a `Listing`** (was `Project` until 2026-09-13): `ListingDocument`, `useListingsStore`, `features/listings`, route `#/listing/:id`. The catalogue side is `Category*` / `catalog.ts`; `Listing.category` is the chosen taxonomy. Identifiers are English — ESLint `no-french-identifiers` enforces it.
- Storage layout: `listings/<id>/{listing.json, original/, generations/, thumbnails/}` (schema v3; `projects/` layouts and IndexedDB v1 migrate on first launch); `schemaVersion` + migrations; images are files, never inside JSON.
- Variations are independent jobs; the UI shows progressive results; retry only for retryable codes.
- Hash router (`#/listing/:id`, `#/settings/:section`); zustand stores; no react-router. **TanStack Query** for credits and platform info (`src/app/query`, skill `tanstack-query`); documents, settings, jobs stay in zustand (the open listing is re-read on SSE events).
- **Post on Vinted = pre-fill, never publish** (desktop window; phones use the native screen of the `vinted-webview` plugin in delegated mode — the app's WebView is paused underneath, so the native side drives the flow). A second `WebviewWindow` with an isolated profile and a navigation allow-list; vinted.com never gets Tauri IPC; the script is compiled into the binary and only fills title, description and photos. DOM selectors live in one file (`src/infrastructure/publish/vinted/selectors.ts`). Vinted's terms forbid automated tools → one-time warning (`vintedAutomationAcknowledged`). Photos to post = the “À publier” marks (`ListingDocument.toPost`, since schema v2). Stays on the device after the backend pivot: the client downloads the marked photos from the API. Window-creating commands must be `async` (WebView2 deadlock in sync commands on Windows).
- **Mobile builds**: `keyring` is a desktop-only dependency (keyring 4 refuses to compile without `v1`/`cli`, and `secrets.rs` has no mobile keychain yet). Android builds on Windows need Developer Mode (cargo-mobile2 symlinks the `.so` into `jniLibs`, no copy fallback) — never build from an elevated terminal instead. `src-tauri/gen/android` is committed; the bundle identifier (`com.aiimagevariations.app`, Tauri warns about `.app`) is kept until a data migration exists (BUILDING.md §6).

## Out of scope

Collaboration, sharing, marketplace, chat UI, ad SDK (only the `Entitlement` model exists), payment before the credit ledger exists (Stripe comes after phase 2), automatic publishing on Vinted (pre-fill only). Accounts, a backend and multi-device access are **in scope since ADR 0001** — delivered through the phases above, not ad hoc.
