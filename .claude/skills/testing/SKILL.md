# Testing

## Stack

Vitest 4 with two projects (`app`: jsdom; `domain`: Node) + `@testing-library/react` + `fake-indexeddb`; coverage via `@vitest/coverage-v8`. Rust: `cargo test`. Setup file `src/test/setup.ts` polyfills `Blob.arrayBuffer` / `URL.createObjectURL` / `DataTransfer` and silences canvas. Baseline on 2026-10-17 (after the local mode was removed): **68 files, 360 tests** — tests of removed code left with it; otherwise a refactor must not lower the count. The client is tested against the fake API (`src/test/fake-api.ts`), never a real provider.

## Where

Colocated `*.test.ts(x)` next to the code:

- **Domain** (`packages/domain/src`, Vitest project `domain`: **Node** environment, no `@/` alias, no setup file — never rely on a DOM polyfill; `pnpm exec vitest run --project domain` runs it alone): `generation-queue.test.ts` (queue semantics; the `harness()` helper routes requests back to jobs through `prompt = job.id`), `recipes`, `catalog`, `mannequin`, `listing-copy` (prompt + parser), `publish`, `usage-tracker`, `models/models.test.ts` (errors, status derivation, request builder).
- **Providers** (`packages/providers`, Node): `Cloudflare*`/`Gemini*` provider, listing-copy and models tests (inject a fetch; never hit the network).
- **Infrastructure**: `api/api.test.ts` (`ApiClient`, session, SSE), `auth/SecretStore.test.ts` (`session_token` only, legacy purge), `storage/IndexedDbStorage.test.ts` (one DB name per test; kept for the local import) + `rename-migration.test.ts`, `image/image-processing.test.ts`, `publish/publish-bridge.test.ts`, `publish/vinted/prefill.test.ts` (React-style form fixture).
- **App**: `listing-flow.test.ts` and `remote-runs.test.ts` (through the stores against the fake API; image decoding mocked via `vi.mock("@/infrastructure/image/image-processing")`), `import-local.test.ts` (fake-indexeddb), `remote-listing-repository.test.ts`, `listing-actions`, `publish-store`, `publish-bar`, `app-units.test.ts` (i18n, router, ui/toast stores).
- **Features / components**: one test per component that holds logic (`ListingSetupCard`, `GenerationFeed`, `Lightbox`, `PostButton`, account and credits screens…), `src/i18n/errors.test.ts` (error wording and localization).
- `src/lib/lib.test.ts` (log redaction), `packages/domain/src/lib/{ids,retry}.test.ts` (ids, backoff, timeouts), `scripts/mobile-doctor.test.mjs`, `tools/eslint-rules/no-french-identifiers.test.mjs`.
- Rust: `src-tauri/src/secrets.rs` (closed key list), `src-tauri/src/vinted.rs` (allow-list, payload limits, URL stripping, poll parsing).

## Rules

- CI never needs a Google, Cloudflare or Resend account or a real key. Fake keys must be obviously fake and still get redacted (`AIzaSy…0000`).
- Every `GenerationErrorCode` a provider can produce has a mapping test.
- Behaviour with side effects (generate, retry, delete, export, publish) is tested through the stores; pure components are tested only when they hold logic.
- Deterministic timing: inject `sleep`/`random` into the queue; mock latency ≤ 5 ms.
- A bug fix starts with a failing test that reproduces it.
- Components that call query hooks (`useCredits`…) render with `renderWithQuery` from `src/test/render.tsx`; `resetQueryClient()` in `beforeEach`; answers come from the fake API.
- A test belongs to the layer it exercises: a domain test never imports `@/infrastructure` (provider tests live next to the adapters).

## Server (`apps/server`)

- Vitest projects `contracts` and `server` (Node) run with `pnpm test`: config loader, logging and redaction, error mapping, image processing (images generated by sharp in the test — never a binary fixture with personal metadata), object keys, Better Auth options that cannot be exercised without Google.
- `pnpm test:integration` (`apps/server/vitest.integration.config.ts`) needs Docker: `test/global-setup.ts` starts Postgres 17, Redis 7 and SeaweedFS 4.48 with Testcontainers once, applies the migrations and creates the bucket; `test/app-harness.ts` builds the real API with an in-memory mailbox (`lastLink()` follows emailed links), `reset()` empties tables, Redis and mail between tests. Files run one at a time.
- Phase 2 suites: `credits.int` (concurrent reservations, refunds once, monthly grant), `queue.int` (fairness, cap, reconciler), `runs.int` (402 writes nothing, cancel/retry, cross-user 404, budget), `worker.int` (real BullMQ workers in-process with the sharp Mock: success, retry with a new seed, refusal, timeouts, cancel while running, double delivery, copy), `events.int` (SSE on a listening server: order, `Last-Event-ID`, isolation, 4th stream), `maintenance.int`.
- Every protection has a test that fails when it is removed (origin check, IP header overwrite, user filter, EXIF stripping were checked that way).
- `pnpm smoke:server` drives a running compose stack end to end (Mailpit API for emails). CI runs both (`server-integration`, `compose-smoke`). No test needs a Google, Cloudflare or Resend account.

## Run

```bash
pnpm test                                      # all
pnpm exec vitest run src/infrastructure/auth   # one folder
pnpm test:coverage                             # coverage/ (v8)
cd src-tauri && cargo test
```
