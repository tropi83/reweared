> **An AI photo studio for second-hand listings.**
>
> The model provides the intelligence. AI Image Variations provides the workflow.

Drop the photo of an item you want to sell, pick its category (women, men, kids, home, electronics, entertainment, hobbies, sport, pets, designer) and subcategory, and get the **photos a good listing needs** — retouched, on a studio background, in use / worn, folded or detail, plus a **mirror selfie** for clothing, shoes, bags, accessories, jewelry and watches (never for kids' items) — each generated by its own predefined prompt tuned to that kind of object, together with the **title and description** written from the original photo. Sign in, and your listings follow you on the web, the desktop app and your phone. No API key to set up: generations run on the platform, paid with **credits** (60 free every month).

> **Looking for the local-first version?** The earlier release — everything on your device, bring your own Cloudflare/Gemini key, no account — is kept unchanged on the [`byok`](https://github.com/tropi83/reweared/tree/byok) branch.

## How it works

```
web app ─────────┐
desktop / phone ─┴─HTTPS─► Caddy ──► api (accounts, listings, uploads, runs, live events)
                                       │ Postgres · SeaweedFS (private photos) · Redis/BullMQ
                                       ▼
                                     worker × N ──► Cloudflare Workers AI (photos) · Google Gemini (texts)
                                     (the only holder of the platform's provider keys)
```

A run is reserved in one transaction (credits + jobs), queued fairly per user, generated by the worker, followed in the app over Server-Sent Events, and refunded if it fails. See [ARCHITECTURE.md](ARCHITECTURE.md), [SECURITY.md](SECURITY.md) and [PRIVACY.md](PRIVACY.md).

## Quick start

Prerequisites: **Node ≥ 22**, **pnpm ≥ 10**, **Docker** (Desktop on Windows/macOS), and for the desktop app **Rust ≥ 1.88** plus the [Tauri 2 prerequisites](https://v2.tauri.app/start/prerequisites/). Step-by-step builds and installers for Windows, macOS, Linux (Debian/Ubuntu), Android and iOS: **[BUILDING.md](BUILDING.md)**.

```bash
pnpm install
pnpm stack:up                                     # the server stack with Mock providers (no provider account needed)
pnpm dev                                          # web app at http://localhost:1420 (emails in Mailpit: http://localhost:8025)
VITE_API_ORIGIN=http://localhost:8080 pnpm tauri dev   # desktop app on the dev stack
pnpm test                                         # unit tests (Vitest); pnpm test:integration for the server
```

The dev stack runs the Mock image and text providers, so the whole flow works offline from any provider. How the stack is configured, run and deployed: [DEVELOPMENT.md → Server](DEVELOPMENT.md#server).

## Tests & quality gates

360 unit tests across 68 Vitest files, 80 server integration tests (Testcontainers: Postgres, Redis, SeaweedFS) and Rust unit tests (`secrets.rs`, `vinted.rs`), all offline: Mock providers on the server, an in-memory fake API for the app, `fake-indexeddb`. The per-file list lives in [DEVELOPMENT.md](DEVELOPMENT.md#tests) and the `testing` skill.

CI ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) runs on every push/PR: web (typecheck, lint, prettier, knip, tests + coverage, build), Rust (fmt, clippy `-D warnings`, tests), server integration tests, a compose stack smoke test (with the check that provider keys reach the worker only) and a secrets scan. Tags `vX.Y.Z` trigger [`release.yml`](.github/workflows/release.yml), which builds the desktop bundles for the API origin in the `API_ORIGIN` repository variable into a draft GitHub release.

## Platform notes

| Platform            | Session                             | Import                     | Vinted pre-fill                        |
| ------------------- | ----------------------------------- | -------------------------- | -------------------------------------- |
| Windows/macOS/Linux | token in the OS credential store    | drop, paste, native dialog | yes                                    |
| Web                 | httpOnly cookie                     | drop, paste, file input    | no                                     |
| Android/iOS         | token in memory (keystore: planned) | photo library or camera    | yes (native screen; iOS not built yet) |

On Linux the OS credential store is the Secret Service (GNOME Keyring or KWallet must be running to stay signed in after a restart). How to build each of these: [BUILDING.md](BUILDING.md).
